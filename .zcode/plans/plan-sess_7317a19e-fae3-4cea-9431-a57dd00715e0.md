**Hard safety rule:** the checked-in `.env` points at a **remote Railway Postgres/Redis** — it is never modified and never seeded. All DB work happens on disposable local docker containers; env isolation is done via inline env-var prefixes (dotenv does not override preset vars).

1. Write a throwaway `deploy/.env` (local-only creds, e.g. `postgres/postgres`, `lead_app`, random Redis password) and start only the DB services: `docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d postgres redis`.

1. `npx tsc --noEmit` — expect exactly the one known error (fixed in Phase 6, then re-run).
